# Design and trust boundaries

The generator expands a fixed reviewed JSON integer grid into pure `Candidate` comparisons. It interprets neither prose nor Python. Sorting operators and thresholds fixes candidate identities. `Session` enumerates a bounded domain, selects a question minimizing the expected remaining candidate count under a uniform prior, and breaks ties by absolute input then input value. That prior is a heuristic, not a calibrated account of human intent.

An answer filters candidate outputs on exactly one input. Unknown input values do not become false votes. Neither marks the session UNRESOLVED. One remaining candidate is CANDIDATE_SET_NARROWED; no remaining disagreement on the declared domain is NO_FURTHER_DISAGREEMENT. Neither status proves correctness outside recorded examples.

The specification and decisions remain separate. The packaged reviewed candidate fixtures contain requirements and integer grids. Only generator_input enters generation, then only candidates and the domain enter Session. Separate intended_behavior tables are authored regression oracles used by tests and the authored script; the CLI never reads them to select operator answers.

`render_contract` embeds observed examples and an explicit identifier-validated module:function. It writes no effect by itself and never imports the target. The CLI writes new output files only. Running an exported file imports and calls that implementation under the operator's authority, without isolation. Do not run it against untrusted code. Each result must be exactly bool, rather than a truthy substitute.

The browser receives a finite generated session tree from the same Python engine, including byte-identical exports. A SHA-256 file and regeneration check detect stale assets. Browser text uses textContent, no eval or imported candidate code. The source launcher binds only 127.0.0.1 and serves the web directory. It is a local demonstration, not an authenticated production service.


Custom policy-v1 is a separate typed declarative path; it preserves the integer grid/session APIs. It accepts reviewed candidate lists and explicit concrete cases, validates exact shapes and finite limits, evaluates comparisons/membership/and/or, then chooses balanced disagreements with case-ID tie breaks. JSON validation rejects duplicate/unsafe keys, unknown fields and unsupported values before evaluation. No requirements prose or intended labels enter its evaluator. It never synthesizes or executes supplied code.

Python and JavaScript independently evaluate the versioned format. SHA-256 binds sorted reviewed candidates/cases and typed fields. Policy-session-v1 includes that exact policy, digest and decisions; restoring revalidates and replays question IDs/answers. Paired tests compare all authored refund branches, records and byte-identical contracts. The contract template is generated from the Python exporter and digest-checked with browser assets. A coherent rewritten session remains possible; hashes are not signatures. Browser imports/downloads use explicit local files and textContent, without browser storage or requests. Neither blocks export; undo replays the prior history.


Policy-session-v2 is opt-in when the operator explicitly labels a case. Ordered answer/label/reconfirmed actions replay independently in Python and JavaScript. An explicit boolean is observed authority; predictions never become observations. Empty surviving candidate sets do not erase labels or prevent their regression export. Neither still blocks assertions. Original v1 records, integer sessions, policy bytes and default adaptive contracts retain their old meaning.

Revision preview is a comparison over separately validated policies and an intact original session. No answer migrates automatically. Reconfirmation verifies the source record and exact case ID/input before recording a new explicit label with the source digest. Saved v2 replay checks digest syntax and action structure; it does not authenticate the source or a reviewer. Pending previews are page-memory state, not saved assertions. Typed form drafts pass the same policy validator before use. Shared comparison clauses are exact structural matches at corresponding paths, with no semantic simplification.

Built-in browser import matches the complete validated canonical record to a Python-generated trusted tree snapshot, then rebuilds path history. It does not implement a second integer evaluator or accept custom grids. Page-memory unsaved flags are independent for policy, draft, original revision and known-example workflows. Downloads clear only their corresponding saved artifact. No browser storage is introduced. Supplied known examples are a separate generated value, never an input to candidate generation.
