# Limitations

This implementation supports the original one-field integer grid and reviewed compound policy-v1 predicates over integer, boolean and categorical fields with explicitly declared concrete cases. Policy comparisons, membership and and/or groups are bounded; candidate generation beyond the original grid uses reviewed typed forms or manual JSON. It does not translate natural language, generate model code, infer date/time or string semantics, or validate a real business policy. A reviewed schema tag is not evidence of who reviewed it or that the candidate set covers intent.

Observed answers specify only displayed inputs. One survivor or domain-wide agreement cannot establish the intended rule. The preserved candidate-miss example agrees at days=30 but is wrong at days=29. Unknown grid input values and neither remain distinct from false. Custom policy cases reject missing or mistyped values; null and unknown are not supported there.

Boundary/exception suggestions enumerate a bounded Cartesian grid of reported typed values from reviewed seeds, rule literals and declared alternatives, including fields absent from rules. All multi-field interactions in that finite grid, including three-or-more-field changes, are included when budgets permit; larger grids prioritize single/pair-field seed changes before Cartesian enumeration. Enumeration may stop at the attempt, total-case or byte limit; inspect `coverage.truncated`, `stop_reason` and the reported omitted-combination count. Early seeds can consume the budget. `finite_domain_complete` means every combination of the reported field values is present, not coverage of an infinite integer domain, undeclared fields or exceptions, labels or user intent. Suggestions do not infer labels or discover undeclared exceptions. Directly writing a known case table can be simpler and can cover cases outside the suggestion pass. No human case-authoring or productivity improvement is established.

Exported tests import an explicitly chosen module. Importing Python executes its code. The package does not evaluate untrusted implementations, provide a sandbox or make an arbitrary-code safety claim. The default CLI never imports the target; the operator explicitly runs the generated test later.

Revision previews are temporary page-memory comparisons; download original and revised records independently. Reconfirmed source digests record provenance, not reviewer authentication. Structural sharing is positional, so reordered equivalent clauses may repeat.

The browser builds policies with typed forms and imports reviewed policies and saved custom sessions from local JSON files, alongside finite authored examples, served only on literal loopback. It uses no storage or automatic persistence. Closing the page loses answers unless the operator downloaded a session. Chromium desktop/mobile automation checks mechanics, focus and markup. Human comprehension, screen-reader behavior, assistive technology compatibility and other browsers have not been studied.

All requirements and labels are authored fixtures. Live candidate generation, independently labeled tasks, held-out evaluation, matched-budget prose/no-clarification comparisons, production integration, adoption and empirical superiority are NOT RUN. No paper reproduction, novelty claim, security certification or publication approval follows from passing software checks.
